### Legitimacy vs capability

Capability may expand. Legitimacy must not drift with it.

| Legitimacy (protected) | Capability (may expand) |
|------------------------|-------------------------|
| attributable replay | feature breadth |
| deterministic recoverability | automation depth |
| bounded interpretation | tooling ergonomics |
| explicit authority | integration surfaces |
| falsifiable operational behavior | performance optimization |

**Rule:** capability-driven identity drift is forbidden. Growth must preserve causal traceability, replay meaning, deterministic recoverability, authority clarity, and bounded interpretation.

### Authority classes

| Class | Allowed | Forbidden |
|-------|---------|-----------|
| **Observational** | detect, measure, replay, compare, attest | infer ontology; silent canonization |
| **Interpretive** | bounded operational framing; causal narrative | universal claims; predictive mythology |
| **Governance** | approve semantic expansion via lane/tranche | implicit canonization; ambient accumulation |

**Instrumentation rule:** observational surfaces verify replay law; they do not redefine replay law. Metadata timestamps, runtime timing, and ephemeral filesystem details are observational residue — not replay meaning.

### Semantic escalation protocol

```text
Repeated observation ≠ canonical meaning
```

Before any new semantic layer becomes **operational authority**, it must:

1. declare bounded scope
2. specify falsification conditions
3. preserve replay equivalence (or open an authorized Lane 2 migration tranche)
4. avoid ontology inflation
5. identify operational impact on authoritative surfaces
6. survive independent rerun scrutiny

**Mandatory escalation (stop — do not patch silently):**

| Trigger | Action |
|---------|--------|
| replay byte / substrate coupling | one Lane 2 tranche scope doc |
| dual operational folds | Lane 1-class inspection |
| interpretive surface acquiring canonical status | ratification or explicit map update |
| hygiene-only drift | compressed inspect → fix → verify → ledger note |

**Drift posture:** ambient semantic accumulation is forbidden. Drift must appear as an **explicit architectural event** in this map or a scoped governance doc — not background normalization.

## GOVERNANCE RULES

1. **Every domain has exactly one canonical authority.** If you are implementing something that already appears in this map, you are either extending the canonical authority (update this map) or creating a research artifact (document it in the non-authoritative section).

2. **Uncompiled files are not authoritative.** A file that is not in the module tree has no operational authority regardless of its content.

3. **Parser drift is determinism corruption.** Strategy identity parsing now routes through `core/src/strategy_id.rs`. Native canonical parsing accepts `STRAT_...`; historical underscore IDs are admissible only through the explicit compatibility adapter. No new local parser copies may be introduced.

4. **The `ga.rs` suppressor must not be restored.** Compiler visibility over the optimization engine is non-negotiable. Removal of `#![allow(...)]` from `ga.rs` is **Phase 1 gate zero** — no subsequent remediation phase may begin until this is complete and the suppressor is permanently prohibited by this rule (V-005).

5. **Research artifacts preserve lineage without granting authority.** Moving a file to `/research_experiments/` does not delete its history — it clarifies its status.

6. **`CRITICAL domain / TRANSITIONAL implementation` is a distinct recognized state.** A domain may be CRITICAL (determinism-sensitive) while its current implementation is TRANSITIONAL (split, placeholder-bound, or pre-consolidation). These are not contradictory — they mean the domain requires replay equivalence proof on consolidation, not that the current split is acceptable indefinitely.

7. **Certification tooling is not a Rust authority surface.** Scripts classified as `STABLE TOOLING` (e.g. `emit_manifest_v1.py`, `certify_equivalence_v1.py`) are acceptable consumers and orchestrators. They do not hold authority over any domain in this map and must not be treated as canonical implementations.

8. **Semantic changes to CRITICAL surfaces require replay equivalence scope declaration.** Any change touching a `CRITICAL` authority surface must declare before merge: (a) expected replay impact, (b) equivalence expectations, (c) affected certification surfaces, (d) whether prior artifacts remain canonical, (e) whether replay hashes are expected to change. "No replay impact expected" is itself a claim requiring validation — it is not a default exemption.

9. **Semantic escalation protocol is mandatory.** Repeated observation does not create canonical meaning. New operational authority requires the six-step escalation protocol in **CALIBRATION PRESERVATION LAYER** above. Observational tooling (`STABLE TOOLING`, fixtures, CI guards) remains non-authoritative — it verifies replay law; it does not redefine replay law.

10. **Legitimacy is not capability.** Feature breadth, automation, and integration may grow only where they preserve the legitimacy column (attributable replay, deterministic recoverability, bounded interpretation, explicit authority, falsifiable behavior). Presentation surfaces (UI, dashboards, narrative demos) must not acquire interpretive authority without explicit ratification.
