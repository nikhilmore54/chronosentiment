## Hypothesis

On representative scheduling instances of varying size and structure, the optimizer consistently reduces workload variance relative to the initial baseline, with improvement rates and convergence behaviour consistent with a steepest-descent local search on this problem class.

---

## Perspective Shift from M6.1–M6.5

Milestones M6.1 through M6.5 established **intrinsic properties** of the optimizer:

| Milestone | Property                  |
|-----------|---------------------------|
| M6.1      | Architectural correctness |
| M6.2      | Functional correctness    |
| M6.3      | Solution quality          |
| M6.4      | Scalability               |
| M6.5      | Operational robustness    |

M6.6 establishes an **extrinsic property**: how the optimizer performs against representative scheduling instances of varying size and structural character. The question is no longer "does the optimizer work?" but "how does it perform on problems that resemble real operational workloads?"

**Fixture design rules (from M6.3):**
1. Heavy rotation holds LATEST pairings; light rotations hold EARLIEST — ensures chronological ordering is preserved when pairings are relocated.
2. All rotations have ≥ 2 pairings — ensures every rotation can donate a pairing without becoming empty.

**Outcome:** PASS. The optimizer reached the analytically known optimum (variance = 0) in 254 evaluations with 6 improving moves. The acceptance ratio of 2.36% is consistent with the small-instance behaviour observed in M6.4 (2.86% for 4 rotations / 12 pairings).

### BM-3: Large, Uniform

**Instance:** 16 rotations, 64 pairings, 2 legs each.  
**Baseline:** (36, 2, 2, ..., 2) — one rotation holds 36 of 64 pairings.  
**Theoretical optimum:** (4, 4, ..., 4) — variance = 0.

| Metric             | Value    |
|--------------------|----------|
| Baseline score     | 270.9375 |
| Optimized score    | 0.4375   |
| Improvement        | 99.8%    |
| Evaluations        | 23,430   |
| Improvements       | 31       |
| Acceptance ratio   | 0.13%    |
| Legal              | Yes      |
| Pairings conserved | Yes      |

**Outcome:** PASS. The optimizer achieved 99.8% improvement, reducing variance from 270.9375 to 0.4375. The residual variance of 0.4375 indicates that the optimizer did not reach the theoretical optimum within the current search configuration. Possible contributing factors include the finite iteration budget and the characteristics of the current neighbourhood structure. Regardless, the optimizer achieved a 99.8% reduction in workload variance while satisfying all correctness invariants. The CI gate (optimized < baseline) is satisfied; the residual is reported as evidence.

**Finding:** The acceptance ratio of 0.13% at large scale is consistent with the trend documented in M6.4 (2.86% → 0.72% → 0.18% across small/medium/large). As problem size grows, the proportion of candidate moves that improve the objective decreases, which is characteristic of steepest-descent local search approaching a near-optimal region.

**Outcome:** PASS. The optimizer reached variance = 0 despite the heterogeneous leg counts. The substantially larger baseline score (448.0 vs. 112.0 for BM-2 with the same pairing distribution) demonstrates that `WorkloadBalanceObjective` responds to workload magnitude rather than treating all pairings equally. This confirms that heterogeneous pairings contribute proportionally more to the optimization objective than homogeneous two-leg pairings.

## CI Gates

For every benchmark instance, the following correctness invariants are enforced:

1. **Objective improvement:** `optimized_score < baseline_score`
2. **Pairing conservation:** total pairings in optimized roster equals total in baseline
3. **Legality:** optimized roster is legal under a bare `LegalityChecker` (no rules registered)

All three gates pass for all four instances.

## Cross-Instance Analysis

### Acceptance Ratio vs. Problem Size

| Instance | Rotations | Pairings | Acceptance Ratio |
|----------|-----------|----------|-----------------|
| BM-1     | 4         | 16       | 2.36%           |
| BM-2     | 8         | 32       | 0.57%           |
| BM-3     | 16        | 64       | 0.13%           |
| BM-4     | 8         | 32       | 0.57%           |

The acceptance ratio decreases monotonically with problem size. This is consistent with the trend documented in M6.4 and reflects a characteristic property of steepest-descent local search: as the search space grows, the fraction of candidate moves that improve the objective decreases. BM-4 matches BM-2 exactly (same rotation and pairing count, same acceptance ratio), confirming that the acceptance ratio is determined by problem structure rather than leg-count heterogeneity.

### Objective Sensitivity to Leg-Count Heterogeneity

BM-4 and BM-2 have identical pairing distributions (18, 2, 2, 2, 2, 2, 2, 2) but different baseline scores (448.0 vs. 112.0). The substantially larger score in BM-4 demonstrates that `WorkloadBalanceObjective` responds to workload magnitude rather than treating all pairings equally: when the heavy rotation contains 4-leg pairings instead of 2-leg pairings, the leg-count imbalance is larger, and the objective reflects this correctly.

### Convergence at Scale

BM-3 is the only instance that did not reach the theoretical optimum within the current search configuration. The residual variance of 0.4375 at 16 rotations / 64 pairings is consistent with the scalability findings in M6.4 and is not a correctness failure — the optimizer achieved a 99.8% reduction in workload variance while satisfying all correctness invariants. The contributing factors (iteration budget, neighbourhood structure, or local optimum) are not uniquely determined by the available evidence and are documented as an open item.
