# ChronoSentiment — Release Manifests

This directory contains per-release manifest files generated by
[`scripts/generate_release_manifest.sh`](../../scripts/generate_release_manifest.sh).

Each manifest is a self-contained JSON record capturing the exact state of the
repository and verification results at the moment a release candidate was
assessed. Manifests are append-only artifacts — never edited after creation.

---

## Directory layout

```
docs/releases/
  README.md                          ← this file
  YYYY-MM-DDTHHMMSSZ_<commit>.json   ← one file per release candidate
```

Filename format: `<ISO-8601-date-compact>_<7-char-git-commit>.json`
Example: `2026-05-27T061300Z_d533d4c.json`

---

## Manifest schema

| Field | Type | Description |
|---|---|---|
| `manifest_version` | string | Schema version — currently `"1"` |
| `generated_at` | string | UTC ISO-8601 timestamp of manifest generation |
| `git_commit_short` | string | 7-char git commit hash |
| `git_commit_full` | string | Full 40-char git commit hash |
| `git_branch` | string | Branch name at generation time |
| `git_dirty_files` | integer | Count of uncommitted changes (0 = clean) |
| `rust_version` | string | `rustc --version` output |
| `cargo_version` | string | `cargo --version` output |
| `os_name` | string | Operating system identifier |
| `corpus_files` | array | List of `{ path, sha256, line_count }` for each JSONL corpus file |
| `replay_test_result` | string | `"PASS"` or `"FAIL"` |
| `replay_test_passed` | integer | Number of replay tests that passed |
| `replay_test_failed` | integer | Number of replay tests that failed |
| `chronology_fixture_result` | string | `"PASS"`, `"FAIL"`, or `"SKIP"` |
| `strategy_fixture_result` | string | `"PASS"`, `"FAIL"`, or `"SKIP"` |
| `binary_hash_sha256` | string | SHA-256 of the release binary, or `"NOT_BUILT"` |
| `binary_path` | string | Relative path to the binary that was hashed |
| `double_build_determinism` | string | `"PASS"`, `"FAIL"`, or `"SKIP"` |
| `certification_ledger_entries` | integer | Row count in `replay_certification_log.md` |
| `overall_status` | string | `"PASS"` if all required checks passed, else `"FAIL"` |
| `notes` | string | Free-text operator notes (empty string if none) |

## Generating a manifest

```bash
# Standard release candidate assessment
bash scripts/generate_release_manifest.sh

# With operator notes
bash scripts/generate_release_manifest.sh --notes "post-hardening sprint release"

# Skip binary build (faster; marks binary_hash as NOT_BUILT)
bash scripts/generate_release_manifest.sh --skip-build

# Skip double-build determinism check
bash scripts/generate_release_manifest.sh --skip-double-build
```

The script exits 0 if `overall_status` is `PASS`, 1 otherwise.
The manifest JSON is written to `docs/releases/` and its path is printed to stdout.

## Relationship to other release gates

| Gate | Script | Purpose |
|---|---|---|
| Release consistency | `scripts/verify_release_consistency.sh` | Full release gate: build + tests + fixtures + determinism |
| Release manifest | `scripts/generate_release_manifest.sh` | Captures and records the verified state as a JSON artifact |
| Operator bootstrap | `scripts/operator_bootstrap.sh` | Pre-flight env check before any operation |
| Replay smoke suite | `scripts/replay_smoke_suite.sh` | Fast post-deploy smoke: replay tests + hash compare |
| CI determinism | `scripts/ci_determinism_test.sh` | Double-build binary hash comparison |

The recommended release workflow is:

```
1. bash scripts/operator_bootstrap.sh          # env READY?
2. bash scripts/verify_release_consistency.sh  # all gates PASS?
3. bash scripts/generate_release_manifest.sh   # record the state
4. git commit docs/releases/<manifest>.json    # commit the manifest
```

---

## Retention policy

Manifests are committed to the repository and retained indefinitely.
They serve as the auditable record of what was verified before each release.
Do not delete or modify existing manifests.
