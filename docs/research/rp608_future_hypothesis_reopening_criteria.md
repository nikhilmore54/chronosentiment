# RP-608 — Future Hypothesis Reopening Criteria

**Date:** 2026-11-07 · **Amended:** 2026-11-15  
**Purpose:** Answer *what evidence would justify opening a new research hypothesis?*  
**Authority:** 0% · baseline/OF frozen · Gate 2 **v2** (`rp608_gate2_amendment_v2.md`)  

## Default

H2 confirmation assessment does **not** automatically open H1 or H3.  
**Gate 2X** offline work does **not** require H2 completion.  
**Gate 2E / H1** still require an explicit dated open note citing this checklist (+ amendment §2.1).

## After H2 confirmation — decision tree

| H2 confirmation label | Default next |
| --- | --- |
| `NEED_MORE_SESSIONS` | Keep waiting; infrastructure only |
| `PERSISTS_DESCRIPTIVE` | Session-regime remains descriptive; optional governance package; **still no** entry filter |
| `WEAKENS` | Update ledger; do not invent thr scans |
| `ONE_DAY_DEPENDENT` | Acquire more sessions; do not promote the strong day |
| `INCONCLUSIVE` | Clarify with protocol amendment **before** new hypothesis |

A new hypothesis is justified only if it addresses a **distinct** unanswered mechanism with **available** decision-time evidence — not to “keep research busy.”

## H1 — Continuous entry quality (reopen gate)

May open **only if all** hold:

1. Native (or separately approved proxy) decision-time continuous fields present with documented completeness.  
2. Leakage audit passed (`ret_15m_bps`-class forward labels forbidden as predictors).  
3. Chronological windows declared before results (and not recycling H2 confirmation as H1 discovery without firewall).  
4. Explicit question: within-signal continuous magnitudes vs W/L+econ — **not** max-WR thr scan.  
5. Separate open note filed; ledger updated.

**Not sufficient:** NSE Oct28/30 continuous differences alone; H2 descriptive persistence alone.

## H3 — Order-flow alignment (reopen gate)

May open **only if all** hold:

1. Decision-time OF fields complete on the target book (Missing stratum explicit).  
2. Distinctions locked: decision-time OF ≠ post-entry OF ≠ exit behavior.  
3. No OF ±0.30 change authorized by the open.  
4. Chronological plan frozen before results.  
5. Separate open note; ledger updated.

**Not sufficient:** Curiosity during H2 wait; unstable prior OF anecdotes without field integrity.

## H4 — Adaptive execution velocity

**Not reopenable** under current crypto engines (`UNTESTABLE_UNDER_CURRENT_ENGINE_DESIGN`).  
Requires authorized engine redesign + capture + integrity — see `rp608_h4_current_engine_boundary.md`.

## Still unauthorized regardless of reopen

- Entry filters / thr scans as “success”  
- Stops / targets / horizon / live authority changes without Gate process  
- Pooling books  
- Inferring latency from simulated timestamps
